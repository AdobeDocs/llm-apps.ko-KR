# 문제 해결 {#troubleshooting}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]이(가) 현재 Beta에 있습니다.
>
>여기에 표시된 기능, 워크플로우 및 UI가 반드시 제품의 최종 상태를 나타내지는 않습니다. Beta에 참여하려면 llm-apps-beta@adobe.com으로 이메일을 보내십시오.

보이는 증상부터 시작하세요 문제를 해결하는 동안 자격 증명, 토큰, 비공개 MCP URL 또는 중요한 처리기 결과를 공유하지 마십시오.

## 앱 생성 및 온보딩

| 증상 | 해결 방법 |
|---------|-------------|
| 새 저장소가 표시되지 않음 | **GitHub에서 저장소 관리**&#x200B;를 선택하고 Adobe LLM 앱 GitHub 앱에 두 저장소에 대한 액세스 권한을 부여한 다음 대화 상자로 돌아가서 목록을 새로 고칩니다. |
| EDS 리포지토리에는 AEM 코드 동기화가 필요합니다. | EDS 저장소용 AEM 코드 동기화를 설치한 다음 LLM 앱 만들기 대화 상자로 돌아갑니다 |
| EDS 유효성 검사에서 사용자가 관리자가 아니라고 표시됨 | **AEM Live 관리자 열기**&#x200B;를 선택하고 자신을 EDS 사이트의 관리자로 추가한 다음 저장소를 새로 고치십시오 |
| 온보딩이 아직 생성 중입니다. | 약 15분 정도 소요됩니다. 페이지를 떠났다가 나중에 다시 돌아올 수 있습니다. |
| 온보딩 보고서 실패 | 두 저장소에 모두 액세스할 수 있고 HTTPS를 통해 웹 사이트가 공개되어 있는지 확인한 다음, 표시되는 오류 메시지를 사용하여 Beta 팀에 문의하십시오 |

## 작업 및 핸들러

| 증상 | 해결 방법 |
|---------|-------------|
| 작업이 호출되지 않음 | ChatGPT 플러그인을 첨부하고, **AI 모델에 노출**&#x200B;이 활성화되었는지 확인하고, 작업 설명을 개선하고, 메타데이터 변경 내용을 다시 배포합니다. |
| 비어 있거나 오류 응답 | `npm test`을(를) 실행한 다음 MCP 검사기 또는 `curl`을(를) 사용하여 처리기를 호출합니다. [로컬 처리기 개발 및 테스트](/help/reference/development.md)를 참조하세요. |
| 핸들러는 로컬에서 작동하지만 배포 후에는 작동하지 않음 | 최신 커밋이 푸시되었는지, 런타임 구성이 있는지, 작업 코드 식별자가 `actions/<code-identifier>/index.js`과(와) 일치하는지 확인합니다. |
| 생성된 작업은 검토됨으로 표시할 수 없습니다. | 핸들러 및 위젯 생성을 확인했습니다. 생성된 끌어오기 요청에 대한 병합 충돌을 확인하고 작업을 다시 로드한 다음 **검토됨으로 표시**&#x200B;를 다시 선택합니다. |

## 위젯

| 증상 | 해결 방법 |
|---------|-------------|
| 위젯이 렌더링되지 않음 | 스크립트 URL, 위젯 URL, HTTPS, EDS 게시, CSP 도메인 및 CORS 헤더를 확인합니다 |
| 위젯은 렌더링되지만 데이터가 표시되지 않음 | MCP 검사기를 사용하여 핸들러를 호출하고 해당 `structuredContent` 모양을 `bridge.toolResult`에서 읽은 필드와 비교합니다. |
| 위젯은 직접 미리 보기에서 작동하지만 ChatGPT에서는 작동하지 않음 | 직접 미리 보기는 샘플 데이터를 사용할 수 있습니다. 배포된 핸들러 결과를 테스트하고 CORS 및 CSP에서 EDS 원본을 허용하는지 확인합니다. |
| 브라우저 요청이 차단됨 | 필요한 원본만 올바른 CSP 필드에 추가하고 다시 배포합니다. |
| HTTP 헤더 편집기에서 구성을 저장할 수 없음 | [AEM 구성 서비스](https://aem.live/docs/config-service-setup)를 사용하거나 EDS 관리자에게 사이트 헤더 구성을 초기화하도록 요청하십시오 |

개인 또는 중요한 데이터를 포함할 수 있는 경우 전체 `bridge.toolResult` 값을 기록하지 마십시오.

## 배포

| 증상 | 해결 방법 |
|---------|-------------|
| **준비 중** 배포가 실패합니다. | 핸들러 저장소가 연결되어 있고 Adobe Developer Console 액세스가 여전히 유효한지 확인 |
| **앱 빌드** 중 배포가 실패합니다. | 로컬에서 `npm install`, `npm test` 및 `npm run build`을(를) 실행합니다. 종속성, 구문 또는 테스트 오류를 수정하고 변경 사항을 푸시합니다 |
| 배포가 성공했지만 변경 사항이 누락되었습니다. | 예상 커밋이 푸시되었는지 확인하고 동일한 환경에 다시 배포합니다. |
| 작업이 **배포되지 않음** 상태로 유지됩니다. | 작업을 검토하거나 메타데이터 변경 후 다시 배포 |

## ChatGPT 플러그인

| 증상 | 해결 방법 |
|---------|-------------|
| 플러그인이 표시되지 않음 | 개발자 모드를 활성화하고 [chatgpt.com/plugins](https://chatgpt.com/plugins)을(를) 열고 플러그인이 있는지 확인한 다음 **연결**&#x200B;을(를) 선택하십시오. |
| 플러그인 생성 실패 | 개발자 모드가 활성화되었는지 확인하고 **앱을 테스트**&#x200B;에서 MCP 서버 URL을 다시 복사한 다음 **인증 없음**&#x200B;에서 **서버 URL**&#x200B;을(를) 사용합니다. |
| 플러그인은 연결하지만 작업을 호출할 수 없습니다. | 플러그인이 채팅에 첨부되고 작업이 모델에 노출되고 최신 버전이 배포되는지 확인합니다. |
| 플러그인이 잘못된 환경을 사용함 | 의도한 스테이지 또는 프로덕션 MCP 서버 URL로 플러그인을 편집하거나 다시 만듭니다. |

문제가 지속되면 Beta 팀에 문의하기 전에 앱 이름, 환경, 실패한 단계, 시간 및 표시되는 오류 메시지를 기록하십시오. 비밀 또는 중요한 고객 데이터를 포함하지 마십시오.
