# 작업 만들기 {#creating-actions}

>[!IMPORTANT]
>
>[!DNL Adobe LLM Apps]이(가) 현재 Beta에 있습니다.
>
>여기에 표시된 기능, 워크플로우 및 UI가 반드시 제품의 최종 상태를 나타내지는 않습니다. Beta에 참여하려면 llm-apps-beta@adobe.com으로 이메일을 보내십시오.

작업은 제품 찾기, 가용성 확인 또는 서비스 예약과 같이 앱이 LLM 대화 내에서 제공하는 기능입니다. 각 작업의 처리기가 작업을 수행하고 선택적 위젯이 결과를 표시합니다.

[인프라 설정](/help/guides/create-app.md) 후 앱 페이지에서 작업을 만드는 방법을 선택하십시오. Adobe 관리 인프라와 자체 저장소 모두에서 자동 생성을 사용할 수 있습니다.

**이 안내서:** 웹 사이트에서 작업을 생성하거나 직접 만드는 방법을 알아봅니다. 자동 생성의 경우 앱을 배포하고 테스트하기 전에 프로세스를 시작하고 결과를 검토하십시오.

## 액션 빌드 방법 선택

앱을 엽니다. Adobe에서 아직 인프라를 준비 중인 경우 설정이 완료될 때까지 기다립니다.

**[!UICONTROL 작업]** 섹션에서 **[!UICONTROL 작업을 작성하는 방법을 선택하세요.]** 은 두 가지 선택 사항을 제공합니다.

| 선택 | 다음의 경우에 사용 |
|---|---|
| **[!UICONTROL 자동으로 작업 빌드]** | 플랫폼이 웹 사이트를 분석하고 제안된 작업, 핸들러 코드, 테스트 및 위젯을 생성하도록 할 수 있습니다. 권장되는 시작점입니다. |
| **[!UICONTROL 직접 작업을 만듭니다]** | 각 작업을 정의하고 구현을 직접 제공하려고 합니다. |

앱 만들기 마법사에서 인프라를 선택해도 이러한 옵션 중 하나가 선택되지 않습니다.

## 웹 사이트에서 작업 생성 {#generate-from-website}

1. **[!UICONTROL 자동으로 작업 빌드]**&#x200B;를 선택합니다.
2. **[!UICONTROL 웹 사이트]**&#x200B;에서 브랜드의 제품, 서비스 또는 고객 작업을 나타내는 공개 HTTPS 웹 사이트를 입력하십시오. 이 예제에서는 `https://frescopa.coffee/`을(를) 사용합니다.
3. **[!UICONTROL 내 작업 빌드]**&#x200B;를 선택합니다.

![작업 — 시작하기 전에 입력한 공개 웹 사이트로 자동 생성 선택됨](/help/assets/guide-creating-actions/build-choice.png)

분석 권한이 있는 웹 사이트를 사용합니다. 기밀 또는 액세스 제어 정보를 노출하는 사이트를 제공하지 마십시오.

**[!UICONTROL 내 작업 빌드]**&#x200B;를 선택하면 생성이 시작됩니다. URL만 입력해도 생성되지 않습니다. 앱을 다시 만들거나 인프라 마법사를 다시 열 필요가 없습니다.

### 이후 생성 진행 상황

앱 페이지에 **[!UICONTROL 작업이 생성되고 있습니다]**. **[!UICONTROL 작업으로 이동]**&#x200B;을 선택하거나 탐색에서 **[!UICONTROL 작업]**&#x200B;을 열어 진행률을 따르세요.

UI는 생성할 때 최대 30분을 예상합니다. 페이지를 떠났다가 필요한 경우 나중에 다시 돌아갑니다.

![작업 — 작업 페이지에서 진행 상황을 확인할 수 있는 링크와 함께 생성이 실행 중입니다.](/help/assets/guide-creating-actions/generating.png)

생성 중 플랫폼은

1. 웹 사이트를 분석하고 앱에 대한 고객 작업을 식별합니다.
2. 설명 및 입력 매개 변수를 포함하여 제안된 작업 메타데이터를 만듭니다.
3. 작업 저장소에서 서버측 처리기 및 테스트를 생성합니다.
4. EDS 저장소에서 위젯을 생성합니다.
5. 검토를 위해 생성된 작업을 준비합니다.

플랫폼이 웹 사이트를 분석하는 동안 작업 페이지에는 **[!UICONTROL 대화 경험에 대한 작업 검색]**&#x200B;이 표시됩니다. 제안된 작업은 플랫폼이 작업을 발견할 때 나타나며 코드 및 위젯 미리 보기가 여전히 생성 중일 수 있습니다. 각 작업을 검토하기 전에 생성이 완료될 때까지 기다립니다.

>[!IMPORTANT]
>
>생성된 처리기는 처음에는 대표적인 샘플 데이터를 사용합니다. 웹 사이트 분석에서는 앱을 프로덕션 API, 라이브 인벤토리, 결제 서비스 또는 예약 시스템에 자동으로 연결하지 않습니다.

생성이 오류를 보고하면 표시되는 오류를 읽고 [문제 해결 지침](/help/reference/troubleshooting.md)을 확인하십시오. 단순히 생성 오류를 무시하기 위해 작업을 승인하지 마십시오.

## 생성된 작업 검토 {#review-generated-actions}

배포하기 전에 제안된 각 작업을 검토하십시오. 유용한 작업을 나타내며 생성된 동작이 앱에서 수행하려는 동작과 일치하는지 확인합니다.

![작업 — 생성된 Frescopa 작업을 검토할 준비가 되었으며 배포되지 않았습니다](/help/assets/guide-creating-actions/actions-ready-for-review.png)

1. **[!UICONTROL 작업]** 페이지에서 준비된 작업에 대해 **[!UICONTROL 검토]**&#x200B;를 선택합니다.
2. 작업의 설명, 입력 매개 변수, 주석, 가시성 및 생성된 처리기를 검토합니다.
3. 작업에 위젯이 있는 경우 위젯 구성을 검토하고 미리 봅니다.
4. 연결된 가져오기 요청을 포함하여 생성된 코드 및 테스트를 검사합니다. 샘플 동작이 무엇인지, 그리고 실제 통합으로 대체해야 하는 동작이 무엇인지 확인하십시오.
5. 작업이 준비되면 **[!UICONTROL 검토됨으로 표시]**&#x200B;를 선택합니다.
6. 작업 목록으로 돌아가서 나머지 작업을 반복합니다.

저장된 작업 편집기는 **[!UICONTROL LLM 위젯 세부 정보]**, **[!UICONTROL 작업 세부 정보]** 및 **[!UICONTROL Analytics]**&#x200B;를 구분합니다. 각각의 탭에서 위젯 및 핸들러 가져오기 요청을 검토합니다.

![생성된 작업 — 현재 편집기 탭과 검토된 대로 표시(저장소 링크 숨김)1&rbrace;](/help/assets/guide-creating-actions/generated-action-review.png)

**[!UICONTROL 검토됨으로 표시]**&#x200B;를 선택하면 병합 차단기가 남아 있지 않은 경우 작업에서 생성된 끌어오기 요청이 병합됩니다. 진행 중인 끌어오기 요청이 검토를 차단하는 경우 차단기를 해결하고 다시 시도하십시오. 해결되지 않은 코드 생성 또는 병합 오류가 있는 구현을 승인하지 마십시오.

생성된 모든 작업을 검토한 후 [작업] 페이지에 **[!UICONTROL 모든 작업이 검토되었습니다!]**&#x200B;이(가) 표시됩니다. 앱으로 돌아가려면 **[!UICONTROL 앱 페이지로 이동]**&#x200B;을 선택합니다.

검토는 배포가 아닙니다. 앱을 배포할 때까지 앱의 MCP 서버를 통해 작업을 사용할 수 없습니다.

## 직접 작업 만들기 {#manual-actions}

웹 사이트에서 작업을 생성하지 않으려면 다음 작업을 수행하십시오.

1. 앱 페이지의 작업 만들기 옵션에서 **[!UICONTROL 직접 작업을 만들겠습니다]**&#x200B;를 선택합니다.
2. **[!UICONTROL 내 작업을 만들겠습니다]**&#x200B;를 선택하세요.
3. 작업 페이지에서 **[!UICONTROL 작업 만들기]**&#x200B;를 선택합니다.
4. [작업을 처음부터 만들기](/help/guides/create-action.md)를 수행하여 메타데이터를 정의하고, 핸들러를 구현하고, 필요한 경우 위젯을 연결합니다.

인프라는 그대로 유지됩니다. 수동 만들기를 선택해도 핸들러 코드가 만들어지거나 비즈니스 시스템이 연결되지 않습니다.

필요에 따라 자동으로 생성된 작업을 검토한 후 수동 작업을 추가합니다.

## 배포 및 테스트

생성된 작업을 검토한 후:

1. [앱을 **[!UICONTROL 단계]**&#x200B;에 배포](/help/guides/deploy-your-app.md)합니다.
2. 스테이징 MCP 서버 URL을 사용하여 [ChatGPT](/help/guides/test-in-chatgpt.md) 또는 [Cloud](/help/guides/test-in-claude.md)에서 테스트합니다.
3. 각 작업과 일치하는 테스트 프롬프트 및 해당 작업을 호출하지 않는 관련 없는 프롬프트. 텍스트 응답과 위젯 상호 작용을 모두 확인합니다.

고객이 앱을 사용할 수 있도록 설정하기 전에 [처리기를 사용자 지정](/help/guides/customize-handler.md)하여 API에 연결하고 [위젯을 사용자 지정](/help/guides/widgets.md)합니다. 스테이지에서 앱을 테스트하여 예상대로 작동하는지 확인합니다. 테스트가 성공한 후에만 프로덕션에 배포
