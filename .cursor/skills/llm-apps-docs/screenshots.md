# 프로덕션 스크린샷 절차

다음 절차를 사용하여 실제 공개 설명서 스크린샷을 캡처합니다.

`https://experience.adobe.com/#/@llmapps/llm-apps/`

선호하는 작업 과정은 인력 확보 작업 후 에이전트 보조 흡입입니다. 사용자는 어떤 프로덕션 상태가 관련성이 있는지 결정합니다. 스킬은 이를 정리하고, 위생화하고, 설명서에 통합합니다.

## 받은 편지함 캡처

각 캡처 실행 위치:

```text
docs-captures/<YYYY-MM-DD>/
```

Git은 디렉터리를 무시합니다. 원시 스크린샷은 로컬 상태로 유지되어야 하며 커밋되어서는 안 됩니다.

사용자는 모든 파일 이름을 사용할 수 있지만 정렬된 이름을 사용하면 쉽게 검토할 수 있습니다.

```text
01-create-app.png
02-connect-github.png
03-onboarding-enabled.png
04-generating-actions.png
05-review-actions.png
```

선택적 `capture-notes.md`은(는) 누락된 상태, 비정상적인 동작 또는 의도된 순서를 설명할 수 있습니다.

## 안전 경계

- 사용자가 브라우저에 Adobe, GitHub 및 LLM 플랫폼 자격 증명을 직접 입력합니다.
- MFA, 암호, CAPTCHA, 조직 선택 및 특권 동의에 대해 중지합니다.
- 토큰, 쿠키, 브라우저 스토리지 또는 자격 증명을 절대 읽기, 인쇄, 저장 또는 커밋하지 마십시오.
- 민감하지 않은 공개 웹 사이트 및 새로운 설명서 전용 저장소를 사용합니다.
- GitHub 앱에 고정자가 사용하는 두 저장소에만 액세스 권한을 부여합니다.
- 저장소 액세스를 생성, 배포, 삭제, 보관 또는 변경하기 전에 문의하십시오.
- 개인 정보, 조직 ID, 저장소 설치 ID, 토큰 또는 전체 런타임 URL은 캡처하지 마십시오.

## 고정장치 이름 지정

일회용 설명서 리소스를 명확하게 식별하는 이름 사용:

```text
App: LLM Apps Docs <YYYY-MM-DD>
Handler repo: llm-apps-docs-<YYYYMMDD>
EDS repo: llm-apps-docs-<YYYYMMDD>-eds
```

어떤 것이든 작성하기 전에 사용자로 대상 Adobe 조직, GitHub 소유자, 공개 웹 사이트 및 고정장치 이름을 확인합니다.

빈 저장소와 비공개 저장소를 모두 만듭니다. README, 라이선스 또는 `.gitignore`(으)로 초기화하지 마십시오.

## 캡처 설정

- 브라우저 크롬 없이 전체 대화 상자를 표시할 수 있을 만큼 큰 데스크탑 뷰포트를 사용하십시오.
- 확대/축소를 100%로 유지합니다.
- 이 문서에서 테마를 특별히 가르치지 않는 한 기본 제품 테마를 사용하십시오.
- 작업과 필요한 컨텍스트를 포함하는 가장 작은 전체 영역을 캡처합니다.
- 회전자가 문서화된 상태가 아니면 커서, 단계와 관련 없는 메뉴 열기, 이전 작업의 토스트 및 임시 회전 장치를 사용하지 마십시오.
- PNG를 사용합니다.
- 파일 이름을 안정적으로 유지합니다. 새로 고침 중에 파일 이름을 바꾸는 대신 이미지 컨텐츠를 바꿉니다.

## 권장 캡처 시퀀스

사용자는 매니페스트에서 다음을 포함하여 관련 상태를 캡처해야 합니다.

1. GitHub가 연결되기 전에 앱을 만듭니다.
2. GitHub 앱 저장소 액세스 선택.
3. **내 앱을 자동으로 빌드**&#x200B;할 수 있습니다. 두 저장소를 모두 선택했습니다.
4. 앱 만들기 또는 자동 앱 빌드 시작입니다.
5. 액션 생성 중.
6. 생성된 작업을 검토할 준비가 되었습니다.
7. 한 가지 대표적인 작업의 메타데이터, 핸들러 및 위젯입니다.
8. 작업별 검토 및 모든 작업이 검토된 상태입니다.
9. 스테이징 배포에 성공했습니다.
10. LLM 플랫폼에서 앱 등록 및 대표적인 결과.

실제 결정, 오류 또는 전제 조건을 설명할 때 추가 화면을 캡처합니다. 모든 클릭을 캡처하지 마십시오.

## 스킬 접수 워크플로우

사용자가 캡처 폴더에서 설명서를 업데이트하도록 요청할 때:

1. 정확한 캡처 디렉토리를 확인합니다.
2. 모든 PNG, JPEG 및 WebP 파일의 인벤토리를 작성하고 각 이미지를 시각적으로 검사합니다.
3. 원본 파일에서 `screenshot-manifest.md`의 항목에 대한 매핑을 빌드합니다.
4. 표시되는 UI 레이블 및 시퀀스를 기존 튜토리얼과 비교합니다.
5. 보고서:
   - 필수 상태 누락;
   - 중복 또는 중복 이미지
   - 모호한 순서
   - 부실 스크린샷
   - 중요한 정보;
   - 문서와 충돌하는 프로덕션 동작.
6. 소스 캡처를 편집하지 마십시오.
7. 허용되는 각 이미지에 대해 `help/assets/guide-onboarding-agent/`에서 안정적인 매니페스트 파일 이름으로 정리된 복사본을 만드십시오.
8. 주변 UI에 유용한 컨텍스트가 추가되지 않는 경우에만 자릅니다.
9. 마스크 구분 값. 안전한 마스킹이 불가능한 경우 재캡처를 요청합니다.
10. 캡처된 워크플로우와 일치하도록 문서 및 대체 텍스트를 업데이트합니다.
11. 링크 및 자산 유효성 검사를 실행합니다.
12. 사용자가 명시적으로 제거할 것을 요청할 때까지 캡처 폴더를 그대로 둡니다.

## 에이전트 기반 캡처 옵션

사용자가 에이전트에게 브라우저를 구동하도록 요청하는 경우 동일한 매니페스트 및 안전 경계를 사용하십시오. 인증, 권한 있는 동의, 저장소 변경, 앱 만들기, 배포 및 정리를 위해 일시 중지합니다. 이 프로덕션 변경 흐름을 자동으로 실행하지 마십시오.

## 이미지 검토

모든 이미지에 대해:

- 하나의 매니페스트 항목과 일치시키십시오.
- 문서에 대해 UI 사본을 확인합니다.
- 필요하지 않은 경우 계정 탐색을 자릅니다.
- 개인 이름, 아바타, 조직 식별자, 저장소 설치 식별자, 런타임 네임스페이스 및 관련 없는 앱을 마스킹합니다.
- 브라우저 자동 채우기, 이메일, 액세스 토큰 또는 개인 저장소 세부 정보가 표시되지 않는지 확인합니다.
- 화면과 상태를 모두 식별하는 대체 텍스트를 작성하십시오.

## 중지 시기

다음과 같은 경우 중단 및 차단 보고

- 프로덕션이 문서화되는 워크플로우와 일치하지 않습니다.
- 검토 흐름은 게시된 설명서와 크게 다릅니다.
- 저장소 유효성 검사는 의도한 빈 저장소 흐름을 거부합니다.
- 온보딩 파이프라인이 실패합니다.
- 권한이 있는 작업에는 사용자 또는 관리자가 필요합니다.
- 단계에 필수적인 정보를 숨기지 않으면 스크린샷을 안전하게 만들 수 없습니다.
